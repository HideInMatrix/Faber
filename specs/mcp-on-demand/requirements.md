# MCP 按需启动

用户已确认继续实施。沿用统一自然语言发现、工具原名、现有审批及用户手动授权；功能实施与发布分阶段，发布按用户明确指令执行。

- 新服务默认按需启动，旧配置缺省仍跟随 Runtime；启用状态与连接状态分开。
- Runtime 启动只为按需服务创建控制器，不启动子进程或握手。连接失败仅影响该按需服务。
- capabilities_search 可在服务离线或应用重启后发现用途。目录缓存仅保留同一连接身份的工具名称、描述及定义摘要，不含地址、参数、环境变量或密钥；首次可填写服务用途说明。
- mcp_connect 使用搜索返回的完整 mcp:<ID>，连接复用、并发合并，不启动整个 Runtime；禁用、用户暂停或未授权的服务不会被 AI 拉起。
- 用户可在 Runtime 运行时连接、暂停及恢复单个服务。暂停撤销工具、取消重连与启动；完整退出彻底清理资源。
- 激活后保持原始工具注册，并提供固定 mcp_call 兼容入口。统一入口仍解析真实服务和工具、校验参数、按真实工具审批，定义变化时拒绝执行，不重放业务调用。
- Skill 沿用搜索摘要和按需读取。内置 Computer Use 保持既有启动和系统权限流程。
- 测试及截图仅保留本地，使用隔离协议服务、进程和界面夹具。
